# Архитектура

Проект маленький и делится на два слоя: **движок заданий** (чистый Python,
без интерфейса) и **форма** (PyQt6, сгенерированная из `.ui`).

```text
Ударения.txt
     │  чтение при импорте
     ▼
Словарь_Ударений.py
  correct_words_list / correct_words_set
  correct_words_hashes
     │  перестановки регистра гласных
     ▼
  all_words / incorrect_words
     │  ApplicationData.task_and_response()
     ▼
{слово: ответ}  ──►  Приложение.py (UI)
```

## 1. Данные

`Ударения.txt` — 229 строк, по одному слову. Ударная гласная записана
заглавной буквой (`аэропОрты`). Файл читается на уровне модуля, поэтому
движок зависит от текущей рабочей папки: запускать из корня репозитория.

## 2. Хэш слова

```python
def hash_key(value):
    return int(''.join(str(ord(c)) for c in value if latin(c)))
```

`latin()` пропускает только кириллицу (диапазон `А…я`, плюс `Ё`/`ё`).
Из кодов символов склеивается число — оно используется как ключ словаря,
чтобы не хранить сами строки дважды и быстро искать вариант.

Ограничение: это не криптографический хэш, а просто компактный ключ.
Для двух разных слов теоретически возможно совпадение, на практике словарь
маленький и коллизий нет — smoke-тест косвенно это подтверждает.

## 3. Верные варианты

`correct_words_list` — слова как есть. `correct_words_set` — те же слова для
операций над множествами. `correct_words` — словарь `{хэш: (слово, True)}`.

## 4. Неверные варианты

Для каждого верного слова:

1. считаются гласные (`аеёиоуыэюя` в обоих регистрах);
2. строится строка команд вида `2` + `1` * (n−1): ровно одна гласная остаётся
   заглавной, остальные становятся строчными;
3. `itertools.permutations` перебирает все позиции этой «заглавной» гласной;
4. каждый вариант добавляется в `all_words_set` и `all_words_hashes`.

Так получаются все мыслимые варианты ударения. Верные слова вычитаются из
общего множества — остаётся `incorrect_words_set` (449 вариантов).
Пары `(слово, False)` складываются в `incorrect_words`.

## 5. Генерация задания

```python
ApplicationData.task_and_response() -> dict[str, str]
```

- `random.sample` берёт 5 разных хэшей из `all_words_hashes`;
- для верного слова в ответ пишется само слово, для неверного — пустая строка;
- задание принимается, только если верных от 1 до 4 и все 5 слов различны
  без учёта регистра (иначе пересэмплирование).

Возвращается словарь `{слово: ответ}`, где ответ — верное слово или `""`.
Порядок ключей — порядок выборки, его можно использовать для отрисовки
вариантов.

## 6. UI

`Приложение.py` — результат `pyuic5` из файла `Приложени.ui` (в репозиторий
не входит). Внутри:

- вкладка «Практика»: пять кнопок-вариантов, кнопка «Продолжить», поле
  результата;
- вкладка «Информация»: статичная теория по заданию №4.

Сейчас форма не подключена к движку: кнопки созданы генератором, обработчики
не назначены, метод `fullen()` — заглушка. Это осознанный следующий шаг,
а не потерянный код.

## 7. Куда подключать UI

Минимальный сценарий:

1. при старте создать `app_data = ApplicationData()`;
2. по нажатию «Продолжить» вызвать `task = app_data.task_and_response()`;
3. разложить `list(task)` по пяти кнопкам;
4. по нажатию кнопки проверить `task[word]`: непустая строка — верно;
5. показать правильный вариант из значения словаря.

Движок уже возвращает всё необходимое — менять его не нужно.

## 8. Известные особенности

- `Приложение.py` сгенерирован PyQt5-генератором, но импортирует `PyQt6` —
  это совместимо, но при повторной генерации нужен `pyuic6`.
- `requirements.txt` — полный freeze окружения 2024 года; приложению нужен
  только `PyQt6`.
- Движок читает `Ударения.txt` относительно текущей папки.
- Файл `.ui` в репозиторий не попал, поэтому форму нельзя перегенерировать
  без него.
