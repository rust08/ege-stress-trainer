# Архитектура

Два слоя: **движок заданий** (`ApplicationData.py`, чистый Python) и **форма**
(`Приложение.py`, PyQt6). Форма сгенерирована из `Приложени.ui`
и доработана вручную: в неё добавлены обработчики кнопок.

```text
Ударения.txt
     │  чтение при импорте
     ▼
ApplicationData.py
  correct_words_list / correct_words_set / correct_words_hashes
     │  перестановки регистра гласных
     ▼
  all_words / incorrect_words
     │  ApplicationData.task_and_response()
     ▼
[слова, номер_ответа, неверное_слово]  ──►  Приложение.py
```

## 1. Данные

`Ударения.txt` — 229 строк, по одному слову. Ударная гласная записана
заглавной буквой (`аэропОрты`). Файл читается на уровне модуля, поэтому
движок зависит от текущей рабочей папки: запускать из корня репозитория.

## 2. Хэш слова

```python
def hash_key(value):
    return int(''.join(str(ord(c)) for c in value if latin(c)))
```

`latin()` пропускает только кириллицу (диапазон `А…я`, плюс `Ё`/`ё`).
Из кодов символов склеивается число — компактный ключ словаря. Это не
криптографический хэш; для словаря такого размера коллизий нет.

## 3. Верные и неверные варианты

Для каждого верного слова:

1. считаются гласные (`аеёиоуыэюя` в обоих регистрах);
2. строится строка команд `2` + `1` * (n−1): одна гласная остаётся заглавной,
   остальные становятся строчными;
3. `itertools.permutations` перебирает все позиции «заглавной» гласной;
4. вариант добавляется в `all_words_set` и `all_words_hashes`.

Верные слова вычитаются из общего множества — получается
`incorrect_words_set` (449 вариантов). Пары `(слово, False)` складываются
в `incorrect_words`.

## 4. Генерация задания

```python
ApplicationData.task_and_response() -> [list[str], int, str]
```

- `random.sample` берёт 5 разных хэшей из `all_words_hashes`;
- для каждого слова проверяется, верное оно или нет;
- задание принимается, только если верных ровно **4** и все 5 слов различны
  без учёта регистра (иначе пересэмплирование);
- ответ собирается как номер неверного слова: для верных в список пишется
  пустая строка, для неверного — его позиция, затем строки склеиваются.

Возвращается список из трёх элементов:

| Индекс | Что | Пример |
|---|---|---|
| `0` | пять слов задания | `["аэропОрты", "бАнты", "позвОнит", ...]` |
| `1` | номер неверного слова (1…5) | `3` |
| `2` | само неверное слово | `"позвОнит"` |

## 5. Форма

`Приложение.py`:

- `setupUi` создаёт виджеты и вызывает `fullen()`, `cont()`, `kn()`;
- `fullen()` — новое задание: берёт `task_and_response()` и раскладывает слова
  по пяти подписям, очищает поле ответа;
- `cont()` — кнопка «Продолжить» вызывает `fullen()`;
- `kn()` — кнопка «Ответить» подключает `ans()`;
- `ans()` — сравнивает введённый номер с `pere[1]` и пишет
  «Правильно!!!» или правильный ответ;
- вкладка «Информация» — статичная теория и кнопки по частям речи
  (обработчики пока не подключены, метод `ruls()` — заготовка).

`Приложени.ui` — исходник формы для Qt Designer. `Приложение.py` получен
`pyuic`-генератором и затем дополнен логикой.

## 6. Известные особенности

- Движок читает `Ударения.txt` относительно текущей папки.
- При импорте `ApplicationData.py` сразу генерирует одно задание
  (`x = ApplicationData.task_and_response()`) — побочный эффект, на работу
  формы не влияет.
- `requirements.txt` — только PyQt6; старый полный freeze окружения 2024 года
  не нужен.
- Кнопки правил на вкладке «Информация» не подключены.
